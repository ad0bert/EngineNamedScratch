# v0.10.0: Networking, plugins and custom shaders

Play together over the network: one player hosts inside their own game, the others join. Entities the host spawns
appear for everyone and move smoothly, each player's own character answers at once, and connections are encrypted.
Also: the engine runs without a window, for servers, tools and tests; what a game may or may not want comes as
plugins it chooses; materials can have shaders of their own and games can add full-screen passes; and a new kits
module holds ready-made pieces for particular kinds of games.

## New
- **Engine without a window.** `engine.runHeadless()` runs the same game in real time with nothing drawn, no sound and
  no gamepads; resources still load and meshes keep their data for colliders. `-Dengine.headless=true` does it from
  `run()`, so a game needs no changes.
  - For tests and tools: `engine.startHeadless()`, then `engine.runTicks(n)` (as fast as the machine can) and
    `engine.stop()`, all on one thread.
  - `NullRenderBackend` is the backend that draws nothing.
- **Step numbers and step hooks.** `engine.tick()` numbers the fixed steps (also while paused). A `StepHook` runs
  `beforeSystems` and `afterStep` in every step. `engine.setTimeScale(1.01)` runs steps a little more often in wall
  time without changing their length.
- **Connections** (`engine.net`, UDP, no new libraries). A `NetServer` accepts clients, a `NetClient` connects; both
  are step hooks.
  - Messages are byte arrays, sent `UNRELIABLE` (positions, inputs) or `RELIABLE` (in order, exactly once; large ones
    are split and joined). `BitWriter`/`BitReader` pack them into bits.
  - Connecting is a handshake with a cookie, so forged addresses cannot fill the server or use it to flood others.
    `NetConfig.forGame(engine.config())` only lets the same game and version in. A `ConnectionFilter` can refuse
    players ("Name taken").
  - Every ending has a reason: left, kicked (with a message), server closed, timed out, server full, denied, wrong
    version, wrong password, no answer.
  - Each connection measures round-trip time, packet loss and bytes per second.
  - `LoopbackNetwork` connects servers and clients in memory, with a clock you drive and chosen latency, jitter,
    loss and duplication; an `Interceptor` sees every packet.
- **Shared entities** (`engine.net.replication`). Wrap the server in a `ServerReplication` and each client in a
  `ClientReplication`, and register the same `Spawner`s on both.
  - `spawn("crate", position)` on the host builds the entity everywhere, also for players who join later. It
    disappears everywhere when the host despawns it or removes it from the scene, and a leaving player's entities go
    with them.
  - Clients show the host's entities about 0.1 s in the past, smoothly between updates, so loss and uneven timing do
    not show. Their rigid bodies are kinematic there and their character controllers off: the host moves them.
    That is a `CopyHook` (`CopyHook.PHYSICS`); `guest.addCopyHook(copy -> ...)` stills the game's own components.
  - `host.teleported(entity)`, in the step the game moved it (a respawn, a portal), makes copies go straight to the
    new place instead of sliding there.
  - Components implementing `NetState` send their own fields (health, a door's angle), applied in step with the
    movement.
  - RPCs: named calls both ways, about an entity or none. `call.isFromOwner()` is the usual check on the host.
- **Players without lag.** Give the player a `CapsuleCollider`, a `CharacterController` and a `CharacterMotor`, spawn
  it owned by the client and give the client's replication a command source (`ActionCommandSource` reads keys, mouse
  and gamepad).
  - The client moves its own player at once and sends its input (a `StandardCommand`: move, look, eight buttons) to
    the host, which runs it in the same step. When the host's result differs, the client puts the player back and replays its
    input; the motor's `visual` child slides back instead of jumping.
  - The client keeps its input arriving about two steps early by running its clock slightly faster or slower.
  - On the host, `motor.pressed(StandardCommand.button(1))` tells game code what a player did (button 0 is "jump",
    which `CharacterMotor` jumps with). `setLocalPlayer(player, source)` drives the host's own player the same way.
- **Any input, any movement, any world.** Prediction works with any `PredictedMotor<C>`, not only walking: a motor
  turns a command into movement and writes the state it depends on.
  - What a command holds is up to the game: a record implementing `InputCommand` and a `CommandCodec` for it, set on
    both sides with `setCommandCodec`. `StandardCommand` is the default.
  - `setWorldSpace(space)` tells the replication how distances work (`WorldSpace.EUCLIDEAN` by default; a world that
    wraps around is one): copies blend along it, and corrections, lag compensation and
    `RelevanceFilter.byDistance(radius, space)` measure along it. `Transform.shiftPrevious` keeps the drawing smooth
    when an entity wraps.
  - `ActionCommandSource` takes the game's action names (`setMoveActions`, `setButton`).
- **Less bandwidth.** Each client gets its own updates, as changes from what it confirmed it has (positions to the
  millimetre): entities it has exactly cost nothing, moving ones a few bytes.
  - `setRelevanceFilter(RelevanceFilter.byDistance(60))` sends a client only what is near its own entities;
    `setAlwaysRelevant` for exceptions.
  - `setBandwidthLimit(bytesPerSecond)` caps each client's updates; the most urgent go first (`setPriority`), the
    rest catch up.
- **Fair hits.** `raycastAsSeenBy(clientId, origin, direction, distance)` on the host tests a shot against where that
  player saw the targets (lag compensation, at most `setMaxRewind`, 0.5 s, back).
- **Encryption and passwords.** Connections are encrypted and authenticated by default (X25519 and AES-256-GCM, from
  the JDK): nobody on the way can read, change, replay or end them. `NetConfig.withPassword("...")` makes the host
  require a password, which is never sent.
- **Plugins.** The engine's core is the scene, systems, rendering, physics, sound, input, resources and game states;
  the rest comes as `EnginePlugin`s that the game chooses with `Game.plugins()`. A plugin bundles systems, step hooks,
  overlays, input bindings, message receivers and component serializers, and is installed in order before
  `Game.init` and removed in reverse after `Game.shutdown`.
  - `EnginePlugins.defaults()` is what the engine always did before, now optional: `MouseReleasePlugin` (Esc frees
    the mouse), `FirstPersonInputPlugin` (WASD and friends), `ImpactSoundPlugin` (collision sounds),
    `DebugOverlayPlugin` (F3). `defaultsWithout(DebugOverlayPlugin.class)`, `defaultsAnd(new MyPlugin())`, or
    `List.of()`.
  - `engine.plugin(MyPlugin.class)`, `engine.hasPlugin(id)`; `engine.components()` knows the installed plugins'
    components (`ComponentRegistry.core()` only the engine's own).
  - A plugin that changes the simulation says `networked()`; `NetConfig.forGame(engine)` then lets only hosts and
    clients with the same such plugins connect.
- **Custom shaders.** The engine's main shader is now built from a library that games' shaders include:
  `#include "lib/surface.glsl"` gives a `Surface` (colour, normal, glow, roughness, ...), `standardSurface()` (the
  material as one) and `shade(surface)` (lights, shadows, sky, reflections, transparency). A custom shader changes
  only its part:

  ```glsl
  #version 330 core
  #include "lib/surface.glsl"
  uniform vec3 uGlowColor;
  void main() {
    Surface s = standardSurface();
    s.emissive += uGlowColor * (0.5 + 0.5 * sin(uTime * 3.0));
    shade(s);
  }
  ```

  - `material.shader("shaders/glow.frag")` (or `shader(vertex, fragment)`, with `lib/vertex.glsl`), values in
    `material.params` (floats, ints, vectors, matrices, textures). Saved with scenes.
  - Full-screen passes: `settings.addPostPass("shaders/vignette.frag", PostPass.Stage.DISPLAY)`, on the linear scene
    before bloom (`HDR`) or the final image before anti-aliasing (`DISPLAY`), with `lib/post.glsl` (image, depth,
    projection). `settings.shaderGlobals` reach every custom shader; `uTime` is set on all of them.
  - `#include` works from any directory and from jars; compile errors name the right file and line; hot reloading
    follows included files. A shader that does not compile is logged and the engine's is used instead.
- **Kits** (new artifact `io.github.ad0bert:engine-named-scratch-kits`), built only on the engine's public API:
  - `engine.kits.flight`: `FlightCommand` and `FlightMotor`, predicted ships that loop, roll and drift.
  - `engine.kits.wraparound`: `Wraparound`, a box that wraps around at every face (a `WorldSpace`).
  - `engine.kits.toon`: `ToonShading` (cel-shaded materials, ink outlines) and `ToonPlugin`.
- **Physics:** `CharacterController.save`/`restore`, `PhysicsSystem.replayCharacter` (one character stepped again
  without side effects), `PhysicsSystem.raycast` over a given list of colliders, `PhysicsSystem.refreshShapes`.
- `Scene.contains(entity)`.

```java
// the host
var host = new ServerReplication(engine, new NetServer(UdpTransport.bind(27015), NetConfig.forGame(engine.config())));
host.registerSpawner("player", ctx -> makePlayer());
host.setListener(new NetListener() {
  public void connected(Connection c) { host.spawn("player", spawnPoint, c.id()); }
});
engine.addStepHook(host);

// a player joining
var guest = new ClientReplication(engine,
    new NetClient(UdpTransport.open(), new InetSocketAddress(hostName, 27015), NetConfig.forGame(engine.config())));
guest.registerSpawner("player", ctx -> makePlayer());
guest.setCommandSource(new ActionCommandSource(engine.input()));
guest.client().connect("Ada".getBytes(StandardCharsets.UTF_8));
engine.addStepHook(guest);
```

## Changes
- `Engine.setDebugOverlayVisible(b)` is now `engine.plugin(DebugOverlayPlugin.class).ifPresent(d -> d.setVisible(b))`.
- `AudioSystem` no longer receives collision messages itself; `ImpactSoundPlugin` does (or
  `ImpactSoundPlugin.receiver(audio)` for code that drives an `AudioSystem` by hand).
- `shaders/basic.frag` and `basic.vert` include the new shader library. A game that replaced them with files of its
  own keeps working; moving the change into a material shader keeps it working with future engine shaders.
- FXAA computes its own luma (the tone-mapped image's alpha is no longer needed).
- `Engine.captureMouse` does nothing without a window (headless, or before `run()`).
- The engine's start-up and shutdown are shared by the window and the headless loop; with a window they happen in the
  same order as before.

## Limits
- Hosting is a listen server: players outside the host's network need the port (UDP 27015 in the example) forwarded
  to the host. There is no relay or NAT traversal.
- If the host leaves, the game ends for everyone: there is no host migration. Save the world (`SceneSerializer`) so
  that someone can host it again.
- Without a password, encryption stops eavesdroppers but not someone actively in between. With one, someone who
  records a connection attempt can try passwords offline, so use more than a word.
- Only root entities are replicated, a changed `NetState` is sent whole, and lag compensation is for rays only.
- Prediction covers the player's own entities with a `PredictedMotor`; other things the player causes (a thrown
  crate) appear after a round trip.
- Shadow maps are drawn with the engine's shaders: a custom vertex shader that moves vertices does not move their
  shadows. The main shader already uses 15 textures, so a custom one with more than one texture of its own needs
  hardware with more than OpenGL 3.3's minimum of 16 (desktop GPUs have 32).
- The demo does not use networking yet. It shows a custom material shader, a post pass, cel shading, and outlines
  with `-Ddemo.outline=true`.

## Use it

```xml
<dependency>
  <groupId>io.github.ad0bert</groupId>
  <artifactId>engine-named-scratch</artifactId>
  <version>0.10.0</version>
</dependency>
<!-- optional: flight, wraparound worlds, cel shading -->
<dependency>
  <groupId>io.github.ad0bert</groupId>
  <artifactId>engine-named-scratch-kits</artifactId>
  <version>0.10.0</version>
</dependency>
```

Games written for v0.9.0 behave as before: the default plugins do what the engine did. They compile unchanged unless
they call `Engine.setDebugOverlayVisible` or `AudioSystem.receiveMessage` (see Changes). Networking, plugins of their
own and custom shaders are only there when a game uses them.
