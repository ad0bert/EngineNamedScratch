# v0.10.0: Networking for co-op games

Play together over the network: one player hosts inside their own game, the others join. Entities the host spawns
appear for everyone and move smoothly, each player's own character or ship answers at once, and connections are
encrypted. Worlds can wrap around at their edges, and things can jump across them. Also: the engine runs without a
window, for servers, tools and tests.

## New
- **Engine without a window.** `engine.runHeadless()` runs the same game in real time with nothing drawn, no sound and
  no gamepads; resources still load and meshes keep their data for colliders. `-Dengine.headless=true` does it from
  `run()`, so a game needs no changes.
  - For tests and tools: `engine.startHeadless()`, then `engine.runTicks(n)` (as fast as the machine can) and
    `engine.stop()`, all on one thread.
  - `NullRenderBackend` is the backend that draws nothing.
- **Step numbers and step hooks.** `engine.tick()` numbers the fixed steps (also while paused). A `StepHook` runs
  `beforeSystems` and `afterStep` in every step. `engine.setTimeScale(1.01)` runs steps a little more often in wall
  time without changing their length.
- **Connections** (`engine.net`, UDP, no new libraries). A `NetServer` accepts clients, a `NetClient` connects; both
  are step hooks.
  - Messages are byte arrays, sent `UNRELIABLE` (positions, inputs) or `RELIABLE` (in order, exactly once; large ones
    are split and joined). `BitWriter`/`BitReader` pack them into bits.
  - Connecting is a handshake with a cookie, so forged addresses cannot fill the server or use it to flood others.
    `NetConfig.forGame(engine.config())` only lets the same game and version in. A `ConnectionFilter` can refuse
    players ("Name taken").
  - Every ending has a reason: left, kicked (with a message), server closed, timed out, server full, denied, wrong
    version, wrong password, no answer.
  - Each connection measures round-trip time, packet loss and bytes per second.
  - `LoopbackNetwork` connects servers and clients in memory, with a clock you drive and chosen latency, jitter,
    loss and duplication; an `Interceptor` sees every packet.
- **Shared entities** (`engine.net.replication`). Wrap the server in a `ServerReplication` and each client in a
  `ClientReplication`, and register the same `Spawner`s on both.
  - `spawn("crate", position)` on the host builds the entity everywhere, also for players who join later. It
    disappears everywhere when the host despawns it or removes it from the scene, and a leaving player's entities go
    with them.
  - Clients show the host's entities about 0.1 s in the past, smoothly between updates, so loss and uneven timing do
    not show. Their rigid bodies are kinematic there and their character controllers off: the host moves them.
  - Components implementing `NetState` send their own fields (health, a door's angle), applied in step with the
    movement.
  - RPCs: named calls both ways, about an entity or none. `call.isFromOwner()` is the usual check on the host.
- **Players without lag.** Give the player a `CapsuleCollider`, a `CharacterController` and a `CharacterMotor`, spawn
  it owned by the client and give the client's replication a command source (`ActionCommandSource` reads keys, mouse
  and gamepad).
  - The client moves its own player at once and sends its input (`InputCommand`: move, look, buttons) to the host,
    which runs it in the same step. When the host's result differs, the client puts the player back and replays its
    input; the motor's `visual` child slides back instead of jumping.
  - The client keeps its input arriving about two steps early by running its clock slightly faster or slower.
  - On the host, `motor.pressed(InputCommand.button(0))` tells game code what a player did.
    `setLocalPlayer(player, source)` drives the host's own player the same way.
- **Players that fly, or move any other way.** Prediction works with any `PredictedMotor`, not only walking.
  - `FlightMotor` flies a ship that drifts in empty space. It turns to the command's orientation, pushes along its
    own axes and keeps drifting (`thrust`, `sideThrust`, `maxSpeed`, `drag`, and `brake` while its `brakeButton` is
    held).
  - Flying commands carry a whole orientation, so ships can loop and roll:
    `InputCommand.flying(tick, moveX, moveY, moveZ, aim, buttons)`. Walking commands stay as small as they were.
  - For other movement, extend `PredictedMotor`:
    - `move(command, dt)` moves the entity.
    - `writePredicted`/`readPredicted` carry the state that movement depends on.
    - `replayStep` does what the engine's systems would do to the entity in a step.
- **Worlds that wrap around.** `setWraparound(Wraparound.cube(halfSize))` on the host's and the clients' replication
  (and on `FlightMotor.wraparound`) joins each face of the world to the opposite one.
  - Copies cross an edge the short way instead of flying back across the whole world.
  - Corrections, lag compensation and `RelevanceFilter.byDistance(radius, wraparound)` measure distance the short way
    too.
  - `transform.shiftPrevious(offset)` keeps the drawing smooth when game code wraps an entity itself.
- **Jumps.** Call `hostReplication.teleported(entity)` in the step the game moved an entity somewhere else (a respawn,
  a hyperspace jump).
  - Copies go straight to the new place instead of sliding there.
  - A client's own player jumps there as well.
  - Lag compensation does not blend across the jump.
- **Less bandwidth.** Each client gets its own updates, as changes from what it confirmed it has (positions to the
  millimetre): entities it has exactly cost nothing, moving ones a few bytes.
  - `setRelevanceFilter(RelevanceFilter.byDistance(60))` sends a client only what is near its own entities;
    `setAlwaysRelevant` for exceptions.
  - `setBandwidthLimit(bytesPerSecond)` caps each client's updates; the most urgent go first (`setPriority`), the
    rest catch up.
- **Fair hits.** `raycastAsSeenBy(clientId, origin, direction, distance)` on the host tests a shot against where that
  player saw the targets (lag compensation, at most `setMaxRewind`, 0.5 s, back).
- **Encryption and passwords.** Connections are encrypted and authenticated by default (X25519 and AES-256-GCM, from
  the JDK): nobody on the way can read, change, replay or end them. `NetConfig.withPassword("...")` makes the host
  require a password, which is never sent.
- **Engine:** `Transform.shiftPrevious(offset)` moves only the previous position used for drawing between steps.
- **Physics:** `CharacterController.save`/`restore`, `PhysicsSystem.replayCharacter` (one character stepped again
  without side effects), `PhysicsSystem.raycast` over a given list of colliders, `PhysicsSystem.refreshShapes`.
- `Scene.contains(entity)`.

```java
// the host
var host = new ServerReplication(engine, new NetServer(UdpTransport.bind(27015), NetConfig.forGame(engine.config())));
host.registerSpawner("player", ctx -> makePlayer());
host.setListener(new NetListener() {
  public void connected(Connection c) { host.spawn("player", spawnPoint, c.id()); }
});
engine.addStepHook(host);

// a player joining
var guest = new ClientReplication(engine,
    new NetClient(UdpTransport.open(), new InetSocketAddress(hostName, 27015), NetConfig.forGame(engine.config())));
guest.registerSpawner("player", ctx -> makePlayer());
guest.setCommandSource(new ActionCommandSource(engine.input()));
guest.client().connect("Ada".getBytes(StandardCharsets.UTF_8));
engine.addStepHook(guest);
```

```java
// a space game: ships that drift and loop, in a world that wraps around
Wraparound space = Wraparound.cube(500);
host.setWraparound(space);
guest.setWraparound(space);
Spawner ship = ctx -> {
  var e = new Entity("ship");
  var motor = e.add(new FlightMotor());
  motor.wraparound = space;
  motor.brakeButton = InputCommand.button(1);
  return e;
};
guest.setCommandSource((tick, dt) -> InputCommand.flying(tick, 0, 0, thrust, aim, buttons));
// hyperspace, on the host
hostShip.transform().position().set(somewhereElse);
host.teleported(hostShip);
```

## Changes
- `Engine.captureMouse` does nothing without a window (headless, or before `run()`).
- The engine's start-up and shutdown are shared by the window and the headless loop; with a window they happen in the
  same order as before.

## Limits
- Hosting is a listen server: players outside the host's network need the port (UDP 27015 in the example) forwarded
  to the host. There is no relay or NAT traversal.
- If the host leaves, the game ends for everyone: there is no host migration. Save the world (`SceneSerializer`) so
  that someone can host it again.
- Without a password, encryption stops eavesdroppers but not someone actively in between. With one, someone who
  records a connection attempt can try passwords offline, so use more than a word.
- Only root entities are replicated, a changed `NetState` is sent whole, and lag compensation is for rays only.
- Prediction covers the player's own entities with a `PredictedMotor` (`CharacterMotor`, `FlightMotor` or the
  game's own). Other things the player causes, such as a thrown crate, appear after a round trip.
- A world wraps around as one box (`Wraparound`) with the same size for every client.
- The demo does not use networking yet.

## Use it

```xml
<dependency>
  <groupId>io.github.ad0bert</groupId>
  <artifactId>engine-named-scratch</artifactId>
  <version>0.10.0</version>
</dependency>
```

Games written for v0.9.0 compile unchanged and behave as before; networking is only there when a game uses it.
